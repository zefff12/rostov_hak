# Помощник по документообороту

Интеллектуальный помощник для работников Организации по Инструкции по документационному обеспечению управления
(ДОУ). Он отвечает на вопросы со ссылками на пункты, подсказывает маршрут визирования по Матрице, готовит проекты
приказов и распоряжений по утвержденным модульным шаблонам и проверяет готовые документы.

Все компоненты — open source. Языковая модель работает локально через [Ollama], поэтому документы и вопросы
не покидают контур Организации.

## Возможности

| Сценарий | Как работает |
|---|---|
| **Вопрос по Инструкции** | Гибридный поиск (BM25 по леммам + эмбеддинги `bge-m3`) находит пункты, модель пересказывает их простым языком. В ответе — ссылки `[1]` на пункты и блок «Источники» с % релевантности |
| **Честный отказ** | Если релевантных пунктов нет, бот говорит «в базе знаний нет информации» и подсказывает, куда обратиться |
| **Маршрут визирования** | Строка Матрицы обязательного визирования + последовательность из п. 10.6 и сроки из п. 10.3. Считается детерминированно, без LLM, за доли секунды |
| **Уточняющие вопросы** | Если не хватает вида документа или условия из Матрицы, бот спрашивает и предлагает варианты кнопками |
| **Черновик по шаблону** | 7 модульных документов. Бот задает вопросы по «Примечаниям по заполнению» и собирает DOCX: служебные элементы модуля удалены, зоны даты, номера и ЭП сохранены |
| **Проверка документа** | Загрузка DOCX/PDF/TXT → ошибки, замечания и пройденные проверки со ссылками на пункты Методических рекомендаций |
| **База знаний** | Реестр документов с редакциями, архив и откат, хеши файлов, загрузка новых документов и редакций без правки кода |
| **Роли и доступ** | Работник, работник Департамента ДОУ, администратор; фильтр документов по уровню доступа; журнал аудита |

Интерфейс сделан по макету Figma: главная, чат, документы, создание и проверка документа, инструкции, админка
базы знаний, а также поп-ап виджет для встраивания в корпоративный портал (`web/widget.js`).

## Быстрый старт (Windows)

1. Установите [Ollama] и Python 3.11+.
2. Запустите `run.bat`. Он ставит зависимости, скачивает модели `qwen2.5:7b` и `bge-m3` (~6 ГБ) и поднимает сервер.
3. Откройте:
   - http://127.0.0.1:8000 — помощник;
   - http://127.0.0.1:8000/portal-demo.html — виджет на странице портала;
   - http://127.0.0.1:8000/admin.html — база знаний (роль «Администратор»).

Вручную (любая ОС):

```bash
pip install -r requirements.txt
ollama pull qwen2.5:7b
ollama pull bge-m3
python -m uvicorn app.main:app --port 8000
```

На CPU без видеокарты ответ идет потоком 20–80 секунд; с GPU — несколько секунд. Без Ollama бот тоже работает:
поиск только по BM25, вместо пересказа выдаются найденные пункты как есть.

### Вход

Демо-режим: работник и работник ДОУ входят в один клик, администратор — по паролю. Пароль создается при первом
запуске в `kb/admin_password.txt` (или задается переменной `ADMIN_PASSWORD`). В корпоративной среде вход
предполагается через SSO.

## Публичная ссылка

- **С ноутбука:** `run_public.bat` поднимает Ollama, сервер и туннель Cloudflare и печатает адрес
  `https://….trycloudflare.com`. Работает, пока компьютер включен; при каждом запуске адрес новый.
- **На сервере (Ubuntu 22.04/24.04):**

  ```bash
  bash deploy/deploy.sh <IP-сервера>
  ```

  Скрипт копирует проект по SSH-ключу и запускает `deploy/setup.sh` в фоне (лог — `/root/dou-setup.log`).
  Ставятся файл подкачки, Ollama, модели (7B при ≥12 ГБ ОЗУ, иначе 3B), служба `dou-assistant`, nginx,
  firewall, вход по SSH только по ключу и туннель Cloudflare `dou-tunnel` с HTTPS-адресом. Узнать адрес:

  ```bash
  journalctl -u dou-tunnel | grep trycloudflare
  ```

## Архитектура

```
Браузер (web/: SPA, виджет, админка)
   │  HTTP, потоковые ответы (NDJSON)
FastAPI (app/main.py) ── роли, лимиты, аудит (auth.py)
   │
Диалоговый менеджер (assistant.py)
   ├─ маршрут визирования ── routing.py (Матрица + п. 10.6, п. 10.3, без LLM)
   ├─ мастер шаблонов ───── modules.py (вопросы → DOCX)
   ├─ проверка документа ── checker.py
   └─ ответ по базе знаний
        ├─ поиск: kb.py (BM25 по леммам pymorphy3 + bge-m3, гибридный скор, порог отказа)
        └─ генерация: llm.py → Ollama (qwen2.5), проверка ссылок на пункты
База знаний (kb/): исходники → parsers.py (PDF/DOCX → пункты) → индекс, реестр редакций
```

Стек: Python 3.11+, FastAPI, Uvicorn, PyMuPDF, python-docx, pymorphy3, NumPy, Ollama (`qwen2.5`, `bge-m3`),
чистые HTML/CSS/JS без сборки.

## Качество

Набор из 31 вопроса (`tests/questions.json`): 28 с ответом в базе знаний и 3 вне ее. Каждый ответ сверен вручную
с пунктом-первоисточником. Подробности — в [tests/REPORT_quality.md](tests/REPORT_quality.md).

| Метрика (`qwen2.5:7b`, CPU) | Результат |
|---|---|
| Ответ верный и полный | 23 / 28 |
| Частично верный | 5 / 28 |
| Неверный | 0 / 28 |
| Ссылки на несуществующие пункты | 0 |
| Честный отказ на вопрос вне базы | 3 / 3 |
| Нужный пункт среди первых трех найденных | 100 % |

```bash
python -m tests.eval_retrieval   # качество поиска, секунды
python -m tests.eval_answers     # полный прогон через LLM, ~20 минут на CPU
```

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_MODEL` | `qwen2.5:7b` | модель Ollama; `qwen2.5:3b` — для слабых серверов, `qwen2.5:14b` — для GPU |
| `EMBED_MODEL` | `bge-m3` | модель эмбеддингов |
| `OLLAMA_URL` | `http://127.0.0.1:11434` | адрес Ollama |
| `LLM_NUM_CTX` | `6144` | размер контекста модели |
| `LLM_KEEP_ALIVE` | `2h` | сколько держать модель в памяти между запросами |
| `MIN_RELEVANCE` | `0.40` | порог, ниже которого бот отвечает «нет информации» |
| `ADMIN_PASSWORD` | из `kb/admin_password.txt` | пароль роли «Администратор» |
| `SECRET_KEY` | из `kb/.secret_key` | ключ подписи токенов сессий |
| `RATE_CHAT_PER_MIN` | `12` | лимит вопросов в минуту с одного IP |
| `RATE_LOGIN_PER_MIN` | `10` | лимит попыток входа в минуту с одного IP |

## Структура

```
app/
  main.py       HTTP API, раздача интерфейса
  assistant.py  диалоговый менеджер: намерения, уточнения, RAG-ответ, мастер шаблонов
  kb.py         реестр документов с редакциями, индекс, гибридный поиск
  parsers.py    разбор PDF/DOCX на пункты, Матрица визирования
  modules.py    7 модулей: поля и вопросы, сборка DOCX
  routing.py    маршрут визирования и сроки рассмотрения
  checker.py    проверка загруженного проекта
  auth.py       роли, токены, лимиты, журнал аудита
  llm.py        клиент Ollama
web/            интерфейс, виджет, админка, иллюстрации (web/img)
kb/sources/     исходные документы: Инструкция, Матрица, Методические рекомендации, модули
kb/registry.json  реестр документов и редакций
kb/index/       кеш эмбеддингов (пересчитывается при изменении документов)
deploy/         развертывание на Linux-сервере
tests/          тестовые вопросы, оценка поиска и ответов, отчет о качестве
```

## Безопасность

- Модель и данные локальны: запросы к внешним LLM-сервисам не отправляются.
- `kb/admin_password.txt`, `kb/.secret_key`, журнал аудита, загруженные и сформированные файлы исключены
  из репозитория (`.gitignore`) и создаются на каждой установке заново.
- Загруженные на проверку файлы не сохраняются после проверки; ссылки на сформированные DOCX не угадываются
  перебором.
